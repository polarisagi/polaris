## 决策一：`make docs-refs` 失效路径引用门控（原 ADR-0081 决策一）

- 文档引用不存在的代码路径 100% 机械可检，不靠周期性人工审计。`scripts/docs-refs.sh` 扫描 `docs/arch/*.md`（活文档，不含 `decisions/`）+ 根 `CLAUDE.md` + `internal/*/CLAUDE.md`，并含全仓 `.go` 注释（实现 `tools/comment_refs.go`，同时校验 §锚点与 ADR 编号）；接入 `make check-all` 与 CI。
- 两条刻意排除：① 路径扫描不含 `docs/arch/decisions/`（ADR 记载写作当时的代码事实，路径漂移是预期状态）；② 带点但扩展名不在已知集合的 basename 视为 Go 符号点记法，不报（误报淹没真实缺陷比漏报更致命）。
- 白名单 `tools/baselines/docs-refs-allowlist.txt` 只收"活文档正在记载历史"一类，每条须注明"为何该路径注定不存在"，不得用于掩盖真实文档漂移。
- **免扫 ≠ 免改**：ADR 正文可随认知更新修订——决策记录而非宪法；结论被新事实推翻时在原节追记复核日期 + 推翻理由，不得静默改写使旧决策看似从未存在。真正不可变的只有：ADR 编号不重排/不复用（`decisions/README.md`）、已应用的 DDL 迁移文件、他人 commit 历史。
- 修订门槛分档（根 `CLAUDE.md §文档可修订性`）：ADR 内**事实引用**（行数、路径、是否已接线）属描述性，与代码不符直接订正；**决策结论与重新评估触发条件**属规范性，推翻须带新事实/新约束并追记，不得凭代码现状反推（否则"被驳方案档案"职能失效）。

## 决策三：文档拆分提案（DS-10-001~004）暂缓（原 ADR-0081 决策三、原 ADR-0044）

- 暂缓 M07/M13 拆分、新建 M14、M05/M10 检索去重。判据：收益停留理论层面（无真实上下文溢出/任务失败案例，`INDEX.md §2` 场景表 + 每文件 `§跳读` 已提供局部读取）；代价确定且不小（M07 被外部引用 72 处、M13 42 处，需同步改 INDEX/CLAUDE.md/章节号引用，且历史 ADR 章节号引用不得指错）；DS-10-003 前提已不成立（`internal/execute/CLAUDE.md` 是现成入口）；文档结构是契约，改动须独立 ADR 立项。

## 决策四：注释里的设计名与代码名——符号不门控，改为锚定（原 ADR-0090）

- 不为注释中的**符号**引用建门控：全仓扫描得 366 个"注释出现、代码未出现"的标识符（626 处），其中仅 7 处为真漂移（信噪比约 1:50）：历史注记（合法且必要）、外部产品/论文名（合法）、设计层概念名（合法）、真漂移（缺陷，已修：`handleAgentStreamFSM`→`internal/gateway/session`、`promoteOrCache`→`PromoteOrCache`）。门控会产生 359 条误报、白名单膨胀即名存实亡（同 ADR-0091（原 0089）的僵尸豁免键）。**路径可门控（`os.Stat` 二值）、符号不行（语义判定）。**
- **设计名必须在其代码实现处有一句锚定注释**把两者绑起来。正例：`internal/llm/modelregistry/registry.go`（`Registry` 是 `ModelVersionRegistry` 的业务逻辑层）、`internal/learning/reflexion/reflexion.go`（`ReflexionEngine` 是 AgentHER 的核心引擎）。锚定句把"设计名 ≠ 代码名"从缺陷降级为约定。
- Go 侧不重命名迁就设计名（符合 R2.1：包名单数小写、类型名不与包名叠词）。
- 重新评估：某次重构后真漂移一次性 >50 处，说明缺的是重构工具而非门控——应在重构脚本里同步改注释，不回头建符号门控。

## 决策五：docs/ 与提示词读者定位——AI 优先（原 ADR-0092，决策者：用户）

- 全部 `docs/` 与提示词文档的读者为 AI；人类可读性不是维护目标。
- 一等公民导航结构，不得以可读性理由删除：文件头 `§跳读` 行（含行号偏移）、`[HE-Rule-x]`/`[Concept]` 行内标签、`inv_` 编号表、紧凑表格。
- 反向许可：为人类舒适而存在的内容（重复展开缩写全称、过渡叙述句、同一信息的散文复述）可删，前提不影响 AI 可解析性（不删章节结构、规则条款、编号）。
- 不维护"AI 紧凑版 + 人类导读版"两套产物。
- 前提条件（非永久事实）：项目处于代码开发期，无外部人类贡献者依赖 arch 文档上手。

## 已驳方案

| 方案 | 驳回理由 |
|---|---|
| 符号引用 CI 门控 | 359 条误报，白名单膨胀即失效（0090） |
| "增加过渡句、展开缩写、降信息密度、删 `§跳读`"的人类可读性重排提案 | 与 AI 优先方向相反；`§跳读` 对 AI 是定位成本节省，对人类才是噪音（0092，2026-08-09；提案文件已不存在） |
| AI 紧凑版 + 人类导读版双版本 | 双份维护成本 |
| 脱离触发条件重启 M07/M13 拆分 | 见决策三 |

## 重新评估触发条件

- 拆分：真实上下文溢出/任务失败记录且根因确认为单文档体量；M05/M10 描述不一致导致实现错误；`internal/execute` 出现单文件容纳不下的设计增量；单个 § 章节本身超 15KB（需量化证据，非理论推演）。
- 读者定位：项目开源后出现外部人类贡献者依赖 `docs/arch/` 上手且反馈密度阻碍理解——重提须有真实人类读者群体的新事实；届时优先独立"导读文档"增量，而非重写现有文档。
- 符号门控：见决策四。
