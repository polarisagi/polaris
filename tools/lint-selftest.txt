# tools/lint-selftest.txt —— 每条 lint 规则的负向用例清单
#
# 由 `make lint-selftest`（tools/lint_selftest.go）执行：注入违规样例 → 断言规则
# 报红 → 还原 → 断言转绿。两步都过才算这条规则「能报红」。
#
# 立此清单的原因：负向验证这条纪律在 local_playground/prompt/fix.md 里写了三处，
# 2026-08-12 实测 12 条门控全部自述 landed，其中 3 条从未验证且确实是瞎的
# （ffi_symbol_check 恒扫到 0 个绑定、fsm_io_lint 抓不到一层间接调用、
# must_check_error_lint 计数器误导）。靠自觉的机制实测 100% 空转，故改为判定。
#
# 格式（字段以 " | " 分隔，注意前后各一个空格）：
#   add   | <RuleID> | <tool> | <临时落点，必须不存在> | <fixture 路径>
#   patch | <RuleID> | <tool> | <目标文件> | <from 串> | <to 串>
#
# patch 模式用于「盯住特定位置」的规则——它们无法靠新增文件触发，只能把已修好的
# 代码临时改回缺陷形态。from 串必须在目标文件中唯一命中；代码变动导致找不到时
# 本门控会报错并指出需同步更新本清单（这正是我们要的：规则、代码、用例三者绑定）。
# 串内不得出现 " | "；换行写 \n，制表符写 \t。
