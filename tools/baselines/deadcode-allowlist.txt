# ── 本文件的反面教材（2026-08-12）──
# 本轮曾有人把 46 个 Rust C-FFI 符号整批塞进本文件，只为让 make ffi-check 转绿。
# 真因是 tools/ffi_symbol_check.go 的绑定提取正则写成两参、与 purego 三参调用形态
# 永不匹配，扫描结果恒为「0 Go FFI binding(s)」——46 条全是误报。修好正则后 45 条
# 自行消失，只剩上面这 1 条真条目。教训：门控扫描数为 0 时，先怀疑门控，不要用白名单
# 消化它的输出（ADR-0091）。ffi_symbol_check 现已内置「绑定数为 0 直接判失败」的自检。
